Exercise Summary

Exercise 1: Model Evaluation
Evaluated 3 models (CodeLlama, Qwen 2.5, TinyLLaMA) with identical prompts & questions
Exercise 2: Evaluation Dataset
25 representative questions across 4 policy categories + hallucination traps
Exercise 3: Quantitative Metrics
Correctness, relevance, latency, hallucination rate, retrieval quality
Exercise 4: Trade-off Analysis
Accuracy vs speed, hallucination vs model size, optimal model selection
Exercise 5: RAG Pipeline Analysis
Question → retrieval → LLM response tracing, accuracy patterns
Exercise 6: Codebase Understanding
Multi-file repository Q&A, AST limitations, Sourcegraph motivation

Key Findings

Accuracy vs Speed Trade-off: TinyLLaMA achieved highest accuracy (1.36/2.00) with lowest hallucination rate (20%), while Qwen 2.5 achieved fastest response time (7.7s) with strong relevance (0.75).

Model Selection: For cloud deployment, Qwen 2.5 (0.5B) provides optimal Pareto efficiency between responsiveness and accuracy. CodeLlama (7B) suffered excessive latency (41.4s avg) despite lower relevance.

RAG Pipeline Quality: 100% retrieval hit rate across all models for KB-supported questions. Out-of-scope questions revealed hallucination patterns—TinyLLaMA showed best refusal accuracy.

Codebase RAG Limitations: Standard text-chunk RAG (vector search) succeeds at keyword matching but fails at deep repository Q&A requiring AST awareness, call-graph tracking, and symbol definition lookup.
